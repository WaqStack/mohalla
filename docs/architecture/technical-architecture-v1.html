Admin + publicNext.jsOne deployment also serves the App-Links interstitial and the policy pages that ARCH-CONFLICT-008 requires
BackendNestJS · TypeScriptIts module system is the boundary enforcement — a module that has not imported another cannot inject it

SearchPG FTS + pg_trgmBR-042 sets a best-effort bar. A search cluster at 1,000 users is unjustified
MediaS3 + CDNImmutable objects are the ideal cache profile. Evaluated, not assumed — direct-from-storage is an accepted fallback
IdentifiersUUIDv7Index locality, non-enumerable, client-generatable. Two generation strategies so hosting stays unconstrained
SessionsOpaque, server-backedRevocation within one request cycle is a requirement; JWT cannot deliver it

Deliberately excluded: Kubernetes · Kafka · Elasticsearch · Redis · event sourcing · CQRS · service mesh · GraphQL · microservices · video infrastructure · profiling analytics. Each carries a named revisit trigger in 02 §6. None is excluded on taste.

The hard rules, and their mechanisms

Ten requirements where a plausible implementation would be wrong. Each is met by a mechanism, not by discipline.

RequirementMechanism
Block never disclosed
BR-025		One VisibilityPolicy, composed by every read path. Deleted, hidden, blocked, banned and nonexistent all return an identical 404 with identical timing
Revocation in one request cycle
EDGE-010		Opaque server-backed sessions. Revocation is a row update — this is what rules out JWT
Auto-hide, never auto-delete
SAFETY-FR-004		Report insert + distinct count + visibility change in one transaction with FOR UPDATE. Posts 3, comments 3, events 2, profiles and DMs never
Audit cannot be mutated
SEC-023		Table owned by migration_owner; runtime holds SELECT+INSERT only; CI asserts the grants. Described as append-only, not as cryptographic immutability
Exactly-once message render
EDGE-021		UNIQUE (conversation_id, client_message_id) — in PostgreSQL, never in the transport, so it survives realtime scaling
Phone never visible
PRIV-003		PublicProfileProjection has no such field to populate. Structural, not filtered
Uploads verified by content
SEC-013		Presigned → private quarantine → magic-byte inspection → promotion under a server-chosen random key
Instant language switch, full mirroring
LOCALE-FR-002/003		Activity recreation; logical properties only, enforced by a lint rule that fails the build; dual line-heights per type token
Feed is never empty
FEED-FR-002		Featured is an independent endpoint with its own cache — a slow Following query cannot delay it
No admin-on-admin action
BR-ADM-001		Two independent enforcement points: no FK from enforcement_actions to admins, plus unconditional server-side rejection

Data architecture

33 tables in eight groups · 8 state machines · 13 named race conditions, each with its mechanism · full ERD in diagrams/database-erd.mmd.

Rules carried by the database
  • UNIQUE citext username — concurrent claims (EDGE-007/008)
  • CHECK date_of_birth — age 13 (BR-002)
  • (user_id, post_id) PK — one like (BR-031)
  • UNIQUE (reporter, target) — one report (BR-030)
  • UNIQUE (conversation_id, client_message_id) — idempotency
  • Ordered pair + UNIQUE — one conversation per pair
  • CHECK on resolution reason — mandatory reason (BR-038)
  • Privilege revocation — append-only audit (BR-039)
Four database roles
  • migration_owner — owns schema; pipeline only
  • runtime_app — DML on data; SELECT+INSERT on audit
  • runtime_worker — same restriction
  • read_only_support — diagnosis only

Production runtime never connects as the owner, so the application can neither alter its schema nor mutate the audit trail.
